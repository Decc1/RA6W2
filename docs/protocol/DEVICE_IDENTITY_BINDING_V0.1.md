# HYGRO-RA6W2 设备身份与一次绑定草案 V0.1

## 1. 目标

每台设备只能由一个云端用户账号绑定。设备本身不保存用户账号、手机号或密码；绑定关系只由云端保存。

## 2. 工厂预置内容

每台设备在生产时需要预置并记录：

| 项目 | 示例 | 用途 | 是否可放进二维码 |
| --- | --- | --- | --- |
| `device_id` | `HYGRO-000001` | MQTT Topic、设备识别、售后查询 | 可以 |
| `claim_token` | 128 bit 随机不透明令牌 | 首次绑定时由云端校验 | 可以 |
| MQTT/TLS 设备凭据 | 设备证书/私钥或 Bootstrap 凭据 | 设备向云端证明身份 | 不可以 |
| 硬件批次/型号 | `HYGRO-RA6W2` | 生产和 OTA 分组 | 可以 |

二维码推荐内容：

```text
HYGRO1|v=1|pid=HYGRO-RA6W2|did=HYGRO-000001|claim={claim_token}
```

二维码中不得包含 Wi-Fi 密码、MQTT 用户名密码、TLS 私钥或用户个人信息。

## 3. 首次绑定流程

```text
App 扫描二维码
  → App 通过 HTTPS 把 device_id + claim_token + 当前用户账号交给云端
  → 云端校验 token，原子地将设备绑定给该用户
  → App 通过 BLE 发现并连接同一 device_id 的设备
  → 完成 BLE 加密/绑定
  → App 通过 BLE 写入 Wi-Fi 凭据
  → 设备通过 TLS/MQTT 上线，云端把最新数据提供给 App
```

云端必须拒绝已绑定给其他用户的 `claim_token`。绑定成功后，App 不能仅凭猜测 device_id 夺取设备。

## 4. 恢复出厂规则

恢复出厂只清除本地 Wi-Fi 凭据、BLE 配对信息和本地历史数据；默认**不自动解除云端账号绑定**。用户需要在 App 中主动解绑，或由售后使用受控流程处理，避免设备丢失后被他人重新绑定。

## 5. 固件边界

- `device_identity` 模块只读取工厂写入的 `device_id`，不会自行随机生成。
- 无最终 Flash/安全区设计前，固件不伪造设备 ID，也不会启动真实 MQTT 身份认证。
- MQTT 设备证书、私钥、claim_token 的生成、注入和云端数据库字段，需要与硬件、生产和云端团队共同确认。
