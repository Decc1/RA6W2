# HYGRO-RA6W2 OTA 方案草案 V0.1

## 前提

本文暂按外部 Flash 为 **8 MB（64 Mbit）** 规划；若最终为 8 Mbit（1 MB），本方案必须重新评估。

## 升级流程

```text
云端 OTA 命令（版本、HTTPS URL、image_size、SHA-256）
  → 设备仅在 Wi-Fi 已联网且电池条件满足时下载
  → 下载到外部 Flash 暂存区
  → SHA-256 校验完整镜像
  → Bootloader 标记“新镜像待启动”
  → 重启并试运行新固件
  → 应用完成关键自检后确认新固件
  → 未确认、异常复位或校验失败则回滚旧固件
```

## 强制规则

- 固件包通过 HTTPS/TLS 下载；不得使用裸 HTTP。
- 必须校验服务端提供的 SHA-256，量产阶段还应增加固件签名验证。
- OTA 前检查电池电压、剩余空间和 Wi-Fi 信号；不足时拒绝升级。
- 下载中断后不能覆盖当前运行固件；下次可重新下载或断点续传。
- 固件首次启动不能立即确认，必须完成时钟、传感器、Flash、看门狗等关键自检后确认。
- “待启动/试运行”标志必须由 Bootloader 存入非易失存储；应用重启后 RAM 会丢失，不能只靠应用变量判断是否需要回滚。

## 当前实现状态

已建立 OTA 状态机和适配接口：下载、校验、待启动、试运行确认、失败回滚。尚未接入 HTTPS 下载器、外部 Flash 分区、Bootloader、SHA-256 实现或真实重启。
