# HYGRO-RA6W2 历史曲线与本地存储接口 V0.1

## 1. 目标

设备每 10 秒采样一次 SHT41。`history_service` 将有效样本按固定的 15 分钟窗口聚合为一笔历史记录，供后续外部 Flash 存储、Wi-Fi 补传和 App 历史曲线使用。

采样失败不会进入统计，也不会以假数据补齐。

## 2. 时间窗口

- 窗口长度：900 秒（15 分钟）。
- 系统启动后的 `0~899` 秒为第 1 窗口，`900~1799` 秒为第 2 窗口，依此类推。
- 一条记录在检测到下一窗口的第一笔有效样本时完成；因此最后一个尚未结束的窗口仍在 RAM 中聚合。
- 当前 V0.1 使用 uptime，不使用 NTP 墙上时间。联网校时后，云端可根据上报时间对齐展示；后续版本可增加 UTC 时间戳而不改变聚合字段。

## 3. 记录字段

| 字段 | 单位 | 说明 |
| --- | --- | --- |
| `window_start_uptime_s` | s | 窗口起始 uptime |
| `first_sample_sequence` | - | 窗口中第一笔样本序号 |
| `temperature_average/min/max_centi_c` | 0.01 °C | 温度平均值、最小值、最大值 |
| `humidity_average/min/max_centi_rh` | 0.01 %RH | 湿度平均值、最小值、最大值 |
| `sample_count` | - | 有效样本数；正常约 90 条 |

使用整数而不是浮点数，减少代码体积并保证 BLE、MQTT、Flash 的数据解释一致。

## 4. 容量估算

- 15 分钟/条：96 条/日。
- 30 天：约 2880 条。
- `history_record_t` 当前约 24 字节；仅原始历史数据约 70 KB，加入记录头、CRC、索引及预留空间后也远小于外部 Flash 8 MB。

注：此前“外部 8m”仍须和硬件确认是 **8 MB（64 Mbit）** 还是 **8 Mbit（1 MB）**；两者对 30 天聚合记录都足够，但 OTA 镜像容量规划会明显不同。

## 5. 存储接口与失败策略

`history_append_callback_t` 是同步追加接口。真正的 Flash 层必须在回调返回前完成写入或复制数据，不能保存传入指针。

- 写入成功：记录才会从 RAM 的 pending 状态移除。
- 写入失败或 Flash 驱动尚未接入：保留一条 pending 记录，下一次采样会重试。
- pending 未写入前，模块不会伪造“落盘成功”。当前接口只保留一条 pending，因此量产前 Flash 层必须完成可靠写入；如需要覆盖长时故障，应扩展 RAM 队列或直接尽快恢复 Flash。

## 6. 后续外部 Flash 层必须实现

1. 环形记录区，避免写满后停止记录。
2. 每条记录的 magic、版本、长度、序号和 CRC。
3. 双份 metadata 或日志式提交，支持掉电恢复。
4. 扇区擦除与磨损均衡策略。
5. 查询、读取、确认已上传和空间回收接口。
6. 与 OTA 分区隔离，OTA 与历史记录不得互相覆盖。
